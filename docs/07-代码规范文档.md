## 一、通用规范

### 1.1 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| Java类名 | 大驼峰 (PascalCase) | `ProductController` |
| Java方法/变量 | 小驼峰 (camelCase) | `getProductById` |
| Java常量 | 全大写下划线 | `MAX_UPLOAD_SIZE` |
| Java包名 | 全小写，点分隔 | `com.cstp.controller` |
| Vue组件名 | 大驼峰 (PascalCase) | `ProductCard.vue` |
| Vue变量/方法 | 小驼峰 (camelCase) | `productList`, `fetchProducts` |
| Vue常量 | 全大写下划线 | `API_BASE_URL` |
| CSS类名 | 短横线 (kebab-case) | `.product-card`, `.search-bar` |
| 数据库表/字段 | 全小写下划线 | `user`, `product_id` |

### 1.2 注释规范

**原则**：注释解释"为什么"而不是"做了什么"。代码本身应该清晰表达做了什么。

```java
// ❌ 不好的注释
// 通过ID获取商品
public Product getProductById(Long id) { ... }

// ✅ 好的注释
// 使用Redis缓存，避免每次请求都查数据库。缓存TTL设为30分钟因为商品信息变更频率低
public Product getProductById(Long id) { ... }
```

**必须写注释的场景**：
- 复杂的业务逻辑（超过10行的方法）
- 非显而易见的算法选择
- 临时解决方案（标注TODO + 原因 + 计划修复时间）
- 公共API方法（Javadoc / JSDoc）

### 1.3 代码格式化

- **缩进**：4个空格（禁止使用Tab）
- **行宽**：最大120字符
- **换行**：操作符前置换行
- **空行**：逻辑块之间用空行分隔
- **文件末尾**：保留一个空行

### 1.4 Git提交规范

```

详细描述（可选，72字换行）
```

### 2.2 Controller层规范

```java
@RestController
@RequestMapping("/api/v1/products")
@RequiredArgsConstructor
@Tag(name = "商品管理")  // Knife4j注解
public class ProductController {

    private final ProductService productService;

    @GetMapping
    @Operation(summary = "商品列表")
    public Result<PageResult<ProductListVO>> list(
            @Valid ProductSearchRequest request) {
        return Result.success(productService.listProducts(request));
    }

    @GetMapping("/{id}")
    @Operation(summary = "商品详情")
    public Result<ProductDetailVO> detail(@PathVariable Long id) {
        return Result.success(productService.getProductDetail(id));
    }

    @PostMapping
    @Operation(summary = "发布商品")
    @PreAuthorize("isAuthenticated()")
    public Result<ProductCreateVO> create(
            @Valid @RequestBody ProductCreateRequest request) {
        Long userId = SecurityUtils.getCurrentUserId();
        return Result.success(productService.createProduct(userId, request));
    }
}
```

**Controller层原则**：
1. 只做参数接收、校验、调用Service、返回结果
2. 不含任何业务逻辑
3. 使用`@Valid`进行参数校验（配合JSR-303注解）
4. 权限控制使用`@PreAuthorize`注解

**Service层原则**：

### 2.5 统一响应封装

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Result<T> {
    private int code;
    private String message;
    private T data;
    private long timestamp;

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data, System.currentTimeMillis());
    }

    public static <T> Result<T> error(int code, String message) {
        return new Result<>(code, message, null, System.currentTimeMillis());
    }
}
```

### 2.6 安全编码规范

1. **禁止拼接SQL**：所有数据库操作使用MyBatis-Plus或参数化XML
2. **敏感信息脱敏**：日志中不打印Token、密码、手机号
3. **输入校验**：Controller层使用`@Valid` + JSR-303，不要信任前端传来的任何数据
4. **权限检查**：涉及用户数据的操作，必须校验当前用户是否有权限（如：只能修改自己的商品）

```java
// ✅ 正确的权限检查
public void deleteProduct(Long userId, Long productId) {
    Product product = productMapper.selectById(productId);
    if (!product.getSellerId().equals(userId)) {
        throw new BusinessException(403, "只能删除自己的商品");
    }
    productMapper.deleteById(productId);
}
```

### 3.2 Vue组件规范

```vue
<script setup>
// 1. 导入
import { ref, computed, onMounted } from 'vue'
import { useRouter } from 'vue-router'
import { ElMessage } from 'element-plus'
import { getProductList } from '@/api/product'
import ProductCard from '@/components/ProductCard.vue'

// 2. Props & Emits
const props = defineProps({
  categoryId: { type: Number, default: null }
})
const emit = defineEmits(['update'])

// 3. 响应式数据
const loading = ref(false)
const productList = ref([])
const page = ref(1)

// 4. 计算属性
const hasMore = computed(() => productList.value.length < total.value)

// 5. 方法
const fetchProducts = async () => {
  loading.value = true
  try {
    const res = await getProductList({ page: page.value })
    productList.value = res.data.records
  } catch (error) {
    ElMessage.error('加载失败，请重试')
  } finally {
    loading.value = false
  }
}

// 6. 生命周期
onMounted(() => {
  fetchProducts()
})
</script>

<template>
  <div class="product-list">
    <ProductCard v-for="item in productList" :key="item.id" :product="item" />
    <el-empty v-if="!loading && !productList.length" description="暂无商品" />
  </div>
</template>

<style scoped>
.product-list {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;

</style>
```

**组件编写原则**：
1. 使用`<script setup>`语法（推荐）
2. Props使用`defineProps`并标注类型和默认值
3. 复杂逻辑抽取为`composables`（useXxx）
4. 样式使用`scoped`避免污染
5. API调用统一走`@/api/`目录

### 3.3 API请求规范

```javascript
// @/api/request.js
import axios from 'axios'
import { ElMessage } from 'element-plus'
import { useAuthStore } from '@/stores/auth'

const request = axios.create({
  baseURL: '/api/v1',
  timeout: 10000,
})

// 请求拦截器 - 添加Token
request.interceptors.request.use(config => {
  const authStore = useAuthStore()
  if (authStore.token) {
    config.headers.Authorization = `Bearer ${authStore.token}`
  }
  return config
})

// 响应拦截器 - 统一错误处理
request.interceptors.response.use(
  response => {
    const { code, message, data } = response.data
    if (code === 200 || code === 201) {
      return data  // 直接返回data，简化调用
    }
    ElMessage.error(message || '请求失败')
    return Promise.reject(new Error(message))
  },
  error => {
    if (error.response?.status === 401) {
      // Token过期，跳转登录
      const authStore = useAuthStore()
      authStore.logout()
    }
    ElMessage.error('网络错误，请重试')
    return Promise.reject(error)
  }
)

export default request
```

## 四、代码评审检查清单

### 4.1 后端评审项

- [ ] Controller是否只做参数接收和Service调用？
- [ ] 是否有SQL注入风险（禁止拼接SQL）？
- [ ] 敏感操作是否有权限校验？
- [ ] 是否有必要的参数校验（@Valid / @NotNull等）？
- [ ] 异常是否通过GlobalExceptionHandler统一处理？
- [ ] 日志是否记录了关键操作（但不含敏感信息）？
- [ ] 数据库表变更是否同步了SQL初始化脚本？

### 4.2 前端评审项

- [ ] 组件是否有合理的Props类型定义？
- [ ] API请求是否有错误处理（try/catch）？
- [ ] 是否有加载态（loading）和空态（empty）处理？
- [ ] 列表是否有分页/无限滚动？
- [ ] 图片是否懒加载？
- [ ] 样式是否使用scoped隔离？
- [ ] 是否在多个组件中重复了相同逻辑（应抽取composable）？
