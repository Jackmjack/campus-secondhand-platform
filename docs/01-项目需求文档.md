## 一、文档概述

### 1.1 文档目的

本文档定义"校园智能二手流转平台"的功能需求、非功能需求及项目范围边界。所有开发、测试工作以此文档为基准。文档确认后原则上不再变更，如出现需求变更须经全团队评审。

### 1.2 范围定义

本文档覆盖 **MVP（最小可行产品）第一阶段** 的全部功能，平台从单一二手交易升级为覆盖二手流转、以物换物、商品租赁、清仓特卖、社区论坛、AI智能推荐、拼卡共享、兼职副业等场景的综合性校园生活服务平台。高级AI估价、区块链信任体系、AR/VR展示、拼团、小法庭争议解决等列入第二阶段规划，不在本次开发范围内。

## 二、项目背景与目标

### 2.1 项目背景

校园二手交易市场存在三大核心痛点：

| 痛点类别 | 具体表现 |
|----------|----------|
| **信息筛选困难** | 交易信息散落在微信群、BBS、QQ群中，学生难以快速筛选想要且质量可靠的物品 |
| **交易安全缺失** | 平台缺乏有效用户认证，虚假交易、欺诈行为频发，用户隐私泄露风险高 |
| **匹配效率低下** | 缺乏精准的推荐算法，买家找不到心仪商品，卖家发布的商品无人问津 |
| **闲置资源利用率低** | 学生有大量闲置衣物、课本、运动装备等资源未被有效利用，缺乏租赁共享机制 |
| **社区互动缺失** | 现有二手平台纯粹是交易工具，缺少社区讨论、经验分享、生活互助等社交属性 |
| **学生收入需求** | 大量学生有兼职副业需求，但缺乏可信赖的校内岗位信息渠道 |
| **交易争议无解** | 买卖双方发生纠纷时缺乏公正的社区裁决机制，用户体验受损 |

### 2.2 项目目标

构建 **校园专属的智能生活服务平台**，核心目标：

1. **建立信任闭环**：通过注册时校园网IP验证 + 信用评价体系，保障交易双方安全
2. **提升交易效率**：智能推荐算法 + 校园场景优化，实现快速精准匹配
3. **降低使用门槛**：简洁的交互流程，支持"课间10分钟完成交易"的碎片化场景
4. **激活闲置资源**：通过租赁、换物、拼卡等模式，最大化校园闲置资源利用率
5. **构建校园社区**：论坛 + 信用评价 + 小法庭，打造可信赖的校内交流与交易生态
6. **服务学生经济**：兼职副业 + AI智能推荐，全方位满足学生生活与经济需求

| 角色 | 代号 | 描述 | 核心需求 |
|------|------|------|----------|
| 普通买家 | Buyer | 有购买需求的学生/教职工 | 搜索、浏览、下单、支付、评价 |

## 四、功能需求（MVP第一阶段）

### 4.1 用户认证模块 (M2)

#### F-01 校园网IP注册验证

| 属性 | 内容 |
|------|------|
| **优先级** | P0（核心，非有不可） |
| **用户故事** | 作为校园用户，我希望在校园网环境下注册账号，确保平台用户均为校内人员 |
| **验收标准** | 1. 注册时检测用户IP是否属于校园网段 2. 校园网IP范围内允许注册（学号/工号+密码） 3. 非校园网IP拒绝注册并提示"请在校园网环境下注册" 4. 注册成功后返回JWT Token，后续登录无需IP检测 |
| **工时估算** | 6h（A负责） |

#### F-02 JWT Token管理

| 属性 | 内容 |
|------|------|
| **优先级** | P0 |
| **用户故事** | 作为平台用户，我希望登录后一定时间内保持登录状态，不需要频繁输入密码 |
| **验收标准** | 1. Token有效期24小时 2. 支持Token刷新机制 3. 退出登录后Token失效 4. HttpOnly Cookie存储 |
| **工时估算** | 包含在M2中 |

### 4.6 AI简易估价（MVP简化版）

#### F-13 基于规则的估价

| 属性 | 内容 |
|------|------|
| **优先级** | P1 |
| **用户故事** | 作为卖家，我不确定应该标价多少，希望平台给我一个参考价格 |
| **验收标准** | 1. 输入：原价、使用时长、成色 2. 输出：建议价格区间 3. 公式：建议价 = 原价 × (1 - 折旧率) × 成色系数 4. 折旧率：电子产品每年30-40%，书籍50-70%，其他视情况 |
| **工时估算** | 2h（附加功能） |

## 七、用户流程图

### 7.1 核心交易流程

```
卖家发布商品 → 商品审核 → 商品上架
    ↓
买家搜索/浏览 → 查看商品详情 → 下单/出价协商
    ↓
卖家确认 → 双方约定面交 → 面交完成
    ↓
双方确认完成 → 互相评价 → 信用分更新
```

### 7.2 以物换物流程

```
用户A发布换物商品（标注想换什么）
    ↓
用户B看到换物信息 → 发起换物提议（提供自己的物品）
    ↓
用户A查看提议 → 接受/拒绝/还价
    ↓
双方达成一致 → 约定面交 → 交换物品
    ↓
双方确认完成 → 互相评价
```

### 7.3 租赁流程

```
出租方发布租赁商品（设置租金/天、押金、可租时段）
    ↓
租客浏览租赁专区 → 选择租用天数 → 下单租赁
    ↓
线下交付押金 → 出租方确认交付
    ↓
租期内正常使用 → 到期前24h提醒归还
    ↓
租客归还 → 出租方确认归还 → 订单完成 → 互相评价
```

### 7.4 清仓打折流程

```
卖家创建清仓活动（标题、时间段、折扣力度）
    ↓
选择商品批量加入活动 → 活动生效，商品自动打折
    ↓
买家进入清仓专区浏览 → 看到倒计时+折扣信息
    ↓
下单购买（按折扣价） → 正常走交易流程
    ↓
活动到期 → 未售出商品恢复原价
```

### 7.5 论坛互动流程

```
用户进入论坛 → 选择板块浏览帖子
    ↓
发帖（标题+正文+图片） / 评论他人帖子 / 点赞
    ↓
帖子按最新回复/最热排序展示
    ↓
优质内容获得更多曝光 → 作者积累社区声望
```

### 7.6 兼职副业流程

```
发布方发布兼职岗位（需管理员审核）
    ↓
学生浏览兼职列表 → 筛选分类 → 查看详情
    ↓
一键投递申请（附简短自我介绍）
    ↓
发布方查看申请人 → 确认人选 → 标记"已招满"
```

### 7.7 拼卡共享流程（第二阶段）

```
发起方发布拼卡信息（卡类型、总费用、人数、人均分摊）
    ↓
其他用户浏览拼卡广场 → 申请加入
    ↓
发起方确认参与者 → 满员后自动关闭
    ↓
参与者线下完成费用分摊 → 拼卡完成 → 互评
```

### 7.8 小法庭裁决流程（第二阶段）

```
交易一方发起争议案件 → 提交证据 → 关联订单
    ↓
被诉方24h内提交答辩
    ↓
系统随机选取20名陪审员（信用分>4.0）
    ↓
陪审员查看双方证据 → 投票支持一方
    ↓
12:8以上即为有效裁决 → 裁决生效 → 执行
```

### 7.9 关键交互场景

**场景1：快速购买**（预计耗时 < 3分钟）
1. 打开首页 → 搜索商品 → 浏览详情 → 一键下单 → 等待卖家确认

**场景2：议价购买**（预计耗时 < 10分钟）
1. 浏览详情 → 出价 → 卖家还价 → 达成一致 → 下单 → 面交

**场景3：发布商品**（预计耗时 < 5分钟）
1. 拍照 → 填写信息 → 获得估价建议 → 发布上架
