## 二、项目管理工具配置

### 2.1 推荐方案：飞书多维表格（免费）

**表格结构**：

| 列名 | 类型 | 说明 |
|------|------|------|
| ID | 自动编号 | 任务编号（如 #001） |
| 任务标题 | 文本 | 简短描述 |
| 任务描述 | 多行文本 | 详细需求/验收标准 |
| 模块 | 单选 | 认证/商品/订单/评价/AI推荐/论坛/换物/租赁/清仓/拼卡/兼职/拼团/小法庭/前端/后端/文档 |
| 优先级 | 单选 | P0(必须) / P1(应该) / P2(可以) |
| 状态 | 单向关联 | 待开始 → 开发中 → 待评审 → 已完成 |
| 负责人 | 人员 | A / B / C / D |
| 预估工时 | 数字 | 单位：小时 |
| Sprint | 数字 | 对应Sprint编号 |
| 截止日期 | 日期 | - |
| 依赖 | 文本 | 依赖的其他任务ID |
| 备注 | 多行文本 | - |

**状态流转**：

```
待开始 → 开发中 → 待评审 → 已完成
  ↑        ↓         ↓
  └─── 阻塞中 ←───────┘
```

## 三、沟通工具配置

### 3.1 微信群/飞书群

**群设置**：
- **群名称**：`校园二手平台-开发组`
- **群公告**（置顶）：Git仓库地址、文档目录、环境配置文档链接
- **群昵称**：真名（角色），如 `张三（后端）`

**群规**：
1. 工作时间随时看群消息，非紧急事项2小时内回复
2. @某人提问题要具体，附上截图/错误日志/复现步骤
3. 每日站会后在群内同步简短文字总结
4. 代码合并后@相关人通知

### 3.2 每日站会（15分钟）

**时间**：每天上午 10:00（或团队协商）
**形式**：线下面对面 / 微信群语音

**站会模板（每人30秒）**：

```
👤 张三（A-后端）：
  ✅ 昨天：完成校园网IP检测注册接口开发，自测通过
  📋 今天：数据库表创建，商品模块接口定义
  🚧 阻塞：等待网络中心提供校园网IP段列表（已发邮件）
```

### 3.3 Sprint回顾（每2天，15分钟）

**内容**：
- Sprint目标完成度？
- 有哪些做得好/不好的？
- 下个Sprint的目标和分工？

## 四、接口调试工具配置

### 4.1 Apifox（推荐，免费版够用）

**配置步骤**：

1. 下载 Apifox：https://apifox.com
2. 创建团队：`校园二手平台`
3. 创建项目：`campus-secondhand-api`
4. 导入接口：从Knife4j的OpenAPI地址导入（`http://localhost:8080/v3/api-docs`）
5. 设置环境变量：
   - **开发环境**: `base_url = http://localhost:8080`
   - **测试环境**: `base_url = http://test-server:8080`

**使用场景**：
- **后端自测**：写完接口后，在Apifox中发送请求验证
- **前端联调**：前端切换Mock为真实环境，直接调用
- **契约测试**：设置断言，验证响应格式是否符合接口文档

### 4.2 Postman（备选）

如不使用Apifox，使用Postman + Collection共享：

1. 创建Collection：`Campus-Trade-API`
2. 按模块建Folder：Auth、Product、Order、Review
3. 每个接口定义好Request/Response示例
4. 导出Collection JSON，放在 `docs/postman/` 目录下

## 八、工作节奏

```
周一         周二         周三         周四         周五
─────────────────────────────────────────────────────────
站会(15min)  站会(15min)  站会(15min)  站会(15min)  站会(15min)
Sprint开始   Sprint结束   Sprint开始   Sprint结束   周复盘(30min)
             回顾(15min)              回顾(15min)
─────────────────────────────────────────────────────────
开发          开发          开发          开发         技术分享
CodeReview   CodeReview   CodeReview   CodeReview   (可选,30min)
```

**核心节奏**：
- 每2天一个Sprint
- 每Sprint结束时做15分钟回顾
- 每周五做30分钟周复盘
- 代码随时提交，每天至少被Review一次

## 九、紧急联系流程

```
发现问题（Bug/阻塞）
    ↓
先自查5分钟（看日志、重试、搜文档）
    ↓
未解决 → 在群内@A求助（附：截图+日志+复现步骤）
    ↓
A判断 → 小问题：直接解答
         → 复杂问题：拉语音/面对面讨论
         → 外部依赖问题：A记录为团队风险
```
