# 校园智能二手流转平台 - 4人团队开发实施方案

## 一、前期准备工作

正式动手写代码之前，必须完成以下5件事：

1. **需求确认与范围锁定**  
   将研究报告中的功能细化为用户故事，优先保证核心流程：用户登录认证 → 商品发布 → 商品搜索浏览 → 下单/协商 → 交易完成/评价。非核心功能（如高级AI估价、区块链信任体系）放到第二阶段。

2. **技术栈统一**  
   后端：Spring Boot 3.x + MyBatis-Plus + MySQL  
   前端：Vue 3 + Vite + Element Plus  
   接口文档：Knife4j（Swagger增强版）  
   身份认证：注册时检测校园网IP + 学号密码登录（登录不检测IP）

3. **开发环境搭建统一**  
   JDK 17、Node.js 18+、MySQL 8.0、Git。使用Docker统一MySQL和Redis版本。后端Maven，前端npm/pnpm。

4. **代码仓库创建与分支策略**  
   GitHub/GitLab仓库，采用Git Flow分支策略：`main`、`develop`、`feature/*`、`hotfix/*`。

5. **协作工具配置**  
   - 项目管理：Trello 或飞书多维表格  
   - 沟通：微信群/飞书群  
   - 文档：飞书文档或Notion  
   - 接口联调：Postman或Apifox

## 二、4人分工方案

## 三、开发模式

### 3.1 整体模式：前后端分离 + 敏捷迭代

前后端并行开发，通过接口文档约定契约，前端使用Mock数据，后端专注业务实现。

### 3.2 协作流程

| 阶段 | 前端 | 后端 | 共同行动 |
|------|------|------|----------|
| 需求评审 | 评估交互工作量 | 评估业务/数据工作量 | 确定接口粒度 |
| 接口定义 | 提出数据结构需求 | 编写Swagger/YApi | 评审并锁定接口文档 |
| 并行开发 | 使用Mock数据开发 | 实现业务逻辑 & 单元测试 | Git Flow分支管理 |
| 联调 | 切换真实后端 | 打开Swagger调试 | Postman契约测试 |
| 上线 | 构建静态包 → 部署 | Docker镜像 → 服务器 | CI/CD流水线 |

### 3.3 代码管理规范

- 分支命名：`feature/模块名-功能简述`
- 提交信息：`[模块] 简短描述`
- 合并要求：至少一人Code Review后合并到develop
- 版本标签：每个里程碑打tag

### 4.4 AI估价模块（MVP简化方案）

初期采用**基于规则的估价策略**：预设折旧公式（原价、使用时长、成色），后期积累数据后升级为XGBoost模型。

### 4.5 部署与运维

- 开发环境：本地搭建
- 测试环境：一台云主机部署前后端
- 生产环境：Nginx托管前端静态文件，后端jar包运行
- 数据库：云数据库或自建MySQL

## 七、风险提示与补充建议

1. **接口变更及时同步**：使用Knife4j自动生成在线文档，后端修改后前端实时可见。
2. **身份认证提前调研**：联系学校网络中心获取校园网IP段列表（用于注册时IP检测），提前确认IP段覆盖范围。
3. **数据安全**：敏感字段加密存储，接口脱敏处理，JWT + HttpOnly Cookie存储Token。
4. **定期代码评审**：每周一次，前后端分别review，交叉review接口调用。
5. **保持沟通频率**：每日站会（15分钟），每周项目复盘会（30分钟）。
