## 一、接口设计规范

### 1.1 URL命名规范

| 规则 | 示例 |
|------|------|
| 使用小写字母+连字符 | `/api/v1/products` |
| 资源名用复数 | `/products`, `/orders` |
| 层级关系用路径表示 | `/products/{id}/images` |
| 使用名词而非动词 | `/products` 而非 `/getProducts` |
| 版本号在URL中 | `/api/v1/` |

### 1.2 HTTP方法约定

| 方法 | 用途 | 示例 |
|------|------|------|
| GET | 查询资源 | `GET /products` |
| POST | 创建资源 | `POST /products` |
| PUT | 全量更新资源 | `PUT /products/{id}` |
| PATCH | 部分更新资源 | `PATCH /products/{id}/status` |
| DELETE | 删除资源（软删除） | `DELETE /products/{id}` |

### 1.3 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { },
  "timestamp": 1717300000000
}
```

**状态码规范**:

| HTTP Code | code | 说明 |
|-----------|------|------|
| 200 | 200 | 请求成功 |
| 201 | 201 | 创建成功 |
| 400 | 400 | 请求参数错误 |
| 401 | 401 | 未认证/Token过期 |
| 403 | 403 | 无权限 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 业务冲突（如重复操作） |
| 500 | 500 | 服务器内部错误 |

### 1.4 分页响应格式

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "records": [],
    "total": 100,
    "page": 1,
    "size": 20,
    "pages": 5
  },
  "timestamp": 1717300000000
}
```

### 1.5 认证方式

所有需要登录的接口，请求头携带：

```
Authorization: Bearer <jwt_token>
```

前端通过HttpOnly Cookie自动携带Token，Axios拦截器统一处理。

## 三、接口详细定义

### 3.1 认证模块

#### 3.1.1 注册（需校园网IP）

```
POST /api/v1/auth/register

说明: 注册时服务端检测客户端IP是否在校园网段内。非校园网IP拒绝注册。

Request:
{
  "studentId": "2024001",
  "username": "2024001",
  "password": "password123",
  "nickname": "张三",
  "department": "计算机学院",
  "major": "软件工程",
  "grade": "2024级",
  "email": "zhangsan@campus.edu.cn"
}

Response 201:
{
  "code": 201,
  "message": "注册成功",
  "data": {
    "token": "eyJhbG...",
    "refreshToken": "eyJhbG...",
    "userInfo": {
      "id": 1,
      "studentId": "2024001",
      "nickname": "张三",
      "avatarUrl": "/uploads/avatar/default.png",
      "department": "计算机学院",
      "role": "USER"
    }
  }
}

Response 403:
{
  "code": 403,
  "message": "请在校园网环境下注册，当前IP不在校园网范围内",
  "data": null
}
```

#### 3.1.2 登录（不检测IP）

```
POST /api/v1/auth/login

说明: 通用登录接口，不检测IP，任何网络环境均可登录。

Request:
{
  "username": "2024001",
  "password": "password123"
}

Response 200:
{
  "code": 200,
  "message": "登录成功",
  "data": {

    "userInfo": { ... }

Response 401:
{
  "code": 401,
  "message": "用户名或密码错误",
  "data": null
}
```


## 四、错误码汇总

| code | 说明 | 常见场景 |
|------|------|----------|
| 200 | 成功 | - |
| 400 | 参数错误 | 必填字段为空、数据格式错误 |
| 401 | 未认证 | Token缺失或已过期 |
| 403 | 无权限 | 非本人操作他人数据 |
| 404 | 资源不存在 | 商品/订单ID不存在 |
| 409 | 业务冲突 | 重复下单、重复评价 |
| 413 | 文件过大 | 图片超过5MB |
| 415 | 不支持的格式 | 上传了非图片文件 |
| 429 | 请求过于频繁 | 短时间大量请求 |
| 500 | 服务器错误 | 系统异常 |

## 五、接口联调建议

1. **开发顺序**：认证模块 → 分类/图片 → 商品CRUD → 商品列表/搜索 → 订单 → 协商 → 评价 → 收藏
2. **Mock约定**：前端先使用Mock Server（如MSW）模拟所有API，后端完成一个就切换一个
3. **文档同步**：后端使用Knife4j自动生成Swagger文档，每次接口变更后前端实时可见
4. **测试工具**：推荐使用Apifox，统一管理和测试所有接口
5. **契约测试**：关键接口的前后端响应格式须通过契约测试验证
