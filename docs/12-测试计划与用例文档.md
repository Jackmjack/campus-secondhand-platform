## 一、测试概述

### 1.1 测试目的

本文档旨在定义校园智能生活服务平台（CSLP）的测试策略、范围及具体用例，确保系统功能符合需求文档（PRD）定义，性能满足设计指标，并保障核心交易流程的安全与稳定。

### 1.2 测试范围

覆盖 MVP 第一阶段所有核心功能模块及非功能需求：
- **功能测试**: 认证、商品、搜索、订单、评价、AI推荐、论坛、以物换物、租赁、清仓、兼职、拼卡。
- **接口测试**: 所有 RESTful API 的正确性与健壮性。
- **性能测试**: 关键接口响应时间、并发负载测试。
- **安全测试**: 校园网IP拦截、鉴权过滤、SQL注入防护。
- **兼容性测试**: 移动端主流浏览器适配。

## 三、测试策略

1. **单元测试**: 开发人员针对核心业务逻辑（如信用分计算、折旧率计算）编写 JUnit 用例。
2. **接口测试**: 随开发进度同步进行，验证数据格式、状态码及异常处理。
3. **集成测试**: 前后端联调后，针对完整业务链条（如下单到评价）进行跑通测试。
4. **回归测试**: 每轮 Bug 修复后，针对受影响模块进行二次验证。
5. **用户验收测试 (UAT)**: 邀请部分真实学生用户在校园网环境下试用，收集反馈。

## 五、非功能性测试

### 5.1 性能测试指标

| 测试项 | 操作/场景 | 性能目标 | 验证方法 |
|--------|-----------|----------|----------|
| 响应延迟 | 首页加载 API | P95 < 300ms | JMeter 并发测试 |
| 并发能力 | 50人同时点击搜索 | 系统不报错，响应 < 2s | 压力测试 |
| AI计算延迟 | 推荐接口 | 响应 < 500ms | 监控日志 |

### 5.2 安全测试项

- **越权访问**: 尝试使用用户A的Token修改用户B的商品信息（预期：拦截并返回403）。
- **SQL注入**: 在搜索框输入 `' OR 1=1 --`（预期：正常处理为字符串，无注入漏洞）。
- **XSS攻击**: 在评论区输入 `<script>alert(1)</script>`（预期：内容被转义，脚本不执行）。

### 5.3 兼容性测试项

- **Chrome (Desktop)**: UI 布局完整，功能 100% 正常。
- **手机浏览器 (iOS/Android)**: 响应式适配，菜单操作顺畅，上传图片功能正常。

## 六、Bug等级定义

| 等级 | 名称 | 描述 | 处理要求 |
|------|------|------|----------|
| **L1** | 崩溃/阻塞 | 系统崩溃、死循环、核心交易流程断裂 | 立即停工修复，24小时内解决 |
| **L2** | 严重缺陷 | 主要功能不符合需求、数据计算错误、严重越权风险 | 48小时内修复 |
| **L3** | 一般缺陷 | 次要功能异常、UI 布局错乱、提示信息误导 | 在下个 Sprint 结束前修复 |
| **L4** | 改进建议 | 交互体验优化、文案微调、美化建议 | 视排期情况处理 |
